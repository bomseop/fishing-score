# 연안 워킹 조건 스코어

한국 연안 워킹 낚시(루어·원투)의 어종별 조건 적합도를 계산하는 모바일 전용 웹앱.
같은 소스를 Capacitor 로 감싸 안드로이드 APK 로도 배포한다 — `ANDROID.md` 참조.

```
www/index.html        프론트엔드 (런타임 의존성 없음, 정적 호스팅)
index.html            루트 리다이렉트 → ./www/
khoa_api.py           공공데이터포털 API 공용 계층 (엔드포인트·인증키·지점표)
build_tides.py        조석예보 고·저조 → data/tide-<YEAR>.json  (연 1회)
collect_sst.py        조위관측소 수온  → data/sst-latest.json   (6시간 주기)
sync_regulations.py   법령 별표1·2  → data/regulations.json     (시행일 변경 시)
data/                 위 스크립트들의 출력
scripts/              앱 빌드 보조 (폰트 번들 · 설정 주입 · android 패치 · 아이콘)
assets/               아이콘·스플래시 원본
```

## 웹과 앱

두 배포 형태가 **같은 `www/index.html`** 을 쓴다. 분기는 `NATIVE` 상수 하나뿐이다.

|  | 웹 (GitHub Pages) | 앱 (APK) |
|---|---|---|
| `data/` 경로 | 상대경로 `../data/` | 빌드 시 주입된 Pages 절대주소 |
| 캐시 | 없음 (매번 fetch) | Preferences + Filesystem |
| 폰트 | CDN | APK 에 번들 |
| 오프라인 | 안 됨 | 캐시로 동작 |

## 데이터 경로

| 항목 | 소스 | 방식 | 주기 |
|---|---|---|---|
| 파고·너울주기·해면수온 | Open-Meteo Marine | 브라우저 직접 호출 | 실시간 |
| 풍속·풍향·기압·일출몰 | Open-Meteo Forecast | 브라우저 직접 호출 | 실시간 |
| 조석 고·저조 | data.go.kr `tideFcstHghLw` | 선계산 정적 JSON | 연 1회 |
| 연안 실측 수온 | data.go.kr `dtRecent` | 수집 정적 JSON | 6시간 |
| 금어기·금지체장 | 국가법령정보센터 OPEN API | 수집 정적 JSON | 주 1회 확인 |

Open-Meteo는 인증키가 없고 CORS를 허용하며 **다중 좌표 배치 요청**을 지원한다.
41개 포인트 전체가 요청 2회(Marine + Forecast)로 끝난다.

공공데이터포털 API는 CORS가 막혀 있고 인증키가 필요해 브라우저에서 직접 못 부른다. 그래서 수집기가
정적 JSON을 떨구고 프론트는 같은 오리진에서 읽는다. 백엔드 서버가 필요 없다.

## 폴백 동작

수집 JSON이 없어도 앱은 동작한다. 헤더의 피드 배지로 상태가 보인다.

- `KHOA TIDE 근사` — 달 위상 기반 근사 물때. 서해에서는 오차가 크다.
- `NIFS SST 근사` — Open-Meteo 격자 SST 사용. 동해 냉수대처럼 국지적인
  현상은 8km 격자에서 뭉개지므로 실측 수집을 붙이는 편이 낫다.

## 설치

```bash
export DATA_GO_KR_KEY="공공데이터포털_일반_인증키"

python build_tides.py            # 최초 1회, 수 시간 소요
python collect_sst.py            # 즉시

python -m http.server 8000       # http://localhost:8000  (루트가 ./www/ 로 리다이렉트)
```

인증키: <https://www.data.go.kr> 에서 아래 두 오픈API를 **활용신청** (개발단계 자동승인)

- 조석예보(고, 저조) — <https://www.data.go.kr/data/15156018/openapi.do>
- 조위관측소 최신 관측데이터 — <https://www.data.go.kr/data/15155508/openapi.do>

포털 인증키는 계정당 하나라 두 API가 같은 값을 쓴다. 다만 **API 별로 활용신청은
따로** 해야 하고, 신청하지 않은 API 는 `SERVICE_KEY_IS_NOT_REGISTERED_ERROR` 로 막힌다.

구 바다누리 OpenAPI(`khoa.go.kr/api/oceangrid`)는 2026-04-01 종료됐다. 이제 발급되지 않는다.

`build_tides.py`는 지점 × 날짜 단위로 호출한다. 46개소 × 365일 = 약 16,800건이라
개발계정 일일 한도(10,000)를 넘는다. 중단되면 `.cache/`에 체크포인트가 남으니 같은 명령으로
재실행하면 이어서 받는다. 이틀에 나눠 돌리거나 운영계정으로 상향해서 쓴다.

## 자동 갱신

`.github/workflows/data.yml` 이 6시간마다(KST 03·09·15·21시) 돈다.
설치 절차는 `SETUP.md`, 여기서는 설계 의도만 적는다.

| 단계 | 주기 | 비고 |
|---|---|---|
| 연안 수온 | 매 실행 | `collect_sst.py` |
| 법령 시행일 확인 | 매 실행 | 바뀌었을 때만 별표 재수집 |
| 조석 캐시 | 매 실행 | 완성될 때까지 1,200회씩 이어받기 |
| 다음 해 조석 | 11월부터 | 연초에 물때가 비지 않도록 미리 |

**조석은 첫 실행에서 안 끝난다.** 46개소 × 365일 ≈ 16,800회 호출이라 Actions
잡 시간 제한과 개발계정 일일 한도(10,000)에 둘 다 걸린다. `build_tides.py --budget 1200`
으로 끊어 받고 체크포인트를 `.cache/` 에 커밋해 다음 실행이 이어받는다.
하루 4회 × 1,200회 → 3~4일이면 한 해가 완성된다. 그동안은 근사 물때로 표시된다.

**PAT 을 등록하지 않으면 정확히 60일 뒤 조용히 멈춘다.** GitHub 는 저장소에
60일간 활동이 없으면 예약 워크플로를 자동 비활성화하는데, 기본 `GITHUB_TOKEN`
으로 봇이 만든 커밋은 그 "활동"으로 집계되지 않는다. 에러도 알림도 없이 멈춘다.
워크플로는 `secrets.PAT` 이 있으면 그걸 쓰고 없으면 기본 토큰으로 폴백하므로
등록하지 않아도 당장은 돌아간다. 다만 시한부다. `SETUP.md` 3절 참조.

## APK 빌드

`.github/workflows/apk.yml` 이 태그(`v*`)를 받으면 서명된 APK 를 Releases 에 올린다.

```bash
git tag v1.0.0 && git push origin v1.0.0
```

로컬에 Android SDK 를 깔 필요가 없다. `android/` 는 커밋하지 않고 CI 가
`npx cap add android` 로 매번 만든 뒤 `scripts/patch-android.mjs` 로 패치한다.
키스토어 시크릿이 없으면 디버그 APK 로 빌드되므로 첫 스모크 테스트는 바로 된다.
자세한 내용은 `ANDROID.md`.

## 스코어링

```
Score = Gate_legal × Gate_region × Gate_season × Gate_temp × Gate_safety × Σ(wᵢ · fᵢ) × 100
```

게이트는 곱셈이라 하나라도 0이면 전체가 0이 된다.

- **금어기** — 「수산자원관리법 시행령」 별표 1의 포획 금지 기간
- **해역** — 해당 해역에 워킹으로 성립하지 않는 어종 (동해 주꾸미 등)
- **시즌** — 해당 월에 접안하지 않는 어종
- **치사수온** — 어종별 생존 범위 이탈
- **안전** — 파고 3m 이상, 또는 너울주기 9초 이상 + 너울높이 1.5m 이상

금어기를 표시가 아니라 게이트로 넣은 이유는 명확하다. 법적으로 잡을 수 없는
기간에 "적극 출조 78점"이 뜨면 앱이 위법을 권하는 셈이 된다. 금지체장은
반대로 게이트가 아니다 — 낚는 것 자체는 가능하고 미달 개체를 방생하면 되므로
판정에는 영향을 주지 않고 법규 밴드에 수치로만 표시한다.

가중합 팩터는 수온·물때·조도·파고·풍속·물색·지형 7종이며 각각 0~1로 정규화된다.
가중치는 어종마다 다르고, **물때 가중치에는 해역 계수**가 곱해진 뒤 재정규화된다.

| 해역 | 계수 | 근거 |
|---|---|---|
| 서해 | ×1.35 | 조차 6~9m, 조류가 베이트 이동을 지배 |
| 남해 | ×1.00 | 기준 |
| 동해 | ×0.35 | 조차 0.2~0.3m, 물때가 거의 무의미 |
| 제주 | ×0.85 | |

물때 팩터는 고·저조 이벤트를 사인 보간해 **조위 변화율**로 계산한다.

```
level(t) = (h₁+h₂)/2 + (h₁-h₂)/2 · cos(πτ)
|dh/dt|  ∝ sin(πτ)
```

정조에서 0, 중들물·중날물에서 최대가 되는데, 이게 실제 조류 세기와 같은 형태다.
조위 절대값이 아니라 변화율을 쓰는 게 핵심이다.

## 법령 동기화

```bash
export LAW_OC="국가법령정보센터_OPEN_API_신청ID"

python sync_regulations.py --check     # 시행일만 확인. 변경되면 exit 1
python sync_regulations.py             # 전체 재수집
python sync_regulations.py --dry-run   # 파싱 결과만 출력
```

신청: <https://open.law.go.kr> — 무료, OC는 이메일 아이디의 @ 앞부분.

법령은 자주 바뀌지 않으므로 주 1회 `--check`로 시행일만 보고, 달라졌을 때만
전체를 다시 받는 방식이 낫다. cron에서는 이렇게 엮는다.

```bash
python sync_regulations.py --check || python sync_regulations.py
```

**씨드값 주의.** `data/regulations.json`이 없으면 `www/index.html`에 내장된 씨드 표를
쓰고 피드 배지에 `법규 별표 씨드`, 법규 밴드에 `미검증`이 표시된다. 씨드는
2026.1.1 기준으로 정리한 참고값이며 법적 효력이 없다. 수집기를 한 번은 돌려야 한다.

파서가 어종 줄을 못 찾거나 동일 어종명이 여러 줄에 나오면 해당 항목에
`unsure` 플래그가 붙고 UI에 경고가 뜬다. 별표 서식이 개정마다 조금씩 달라지기
때문에, `--dry-run` 결과를 별표 원문과 한 번 대조하고 넘어가는 편이 안전하다.

**이 파이프라인이 못 잡는 것:**

- **시·도 조례** — 참문어 금어기처럼 관할 지자체장이 조정할 수 있는 항목
- **한시적 유예** — TAC 대상 어종의 금어기·금지체장 적용 유예는 중앙수산조정위원회
  고시로 나가며 시행령 별표에 반영되지 않는다
- **비어업인 특례** — 낚시인에게만 적용되는 어구·어법 제한은 별도 조항이다

그래서 법규 밴드에는 해양수산부 고시 링크가 항상 함께 뜬다. 최종 확인은 사용자 몫이다.

## 이건 확률이 아니다

표시되는 값은 **조건 적합도 점수**지 입질 확률이 아니다. 확률이라고 부르려면
"이 조건에서 몇 번 던져 몇 번 물었다"는 정답 라벨이 필요한데 그런 공개
데이터셋이 없다. 가중치는 어종 생태에 근거한 추정치이며 캘리브레이션되지 않았다.

점수를 확률로 바꾸려면 조과 로그를 모아 로지스틱 회귀로 보정해야 한다.
`score()`가 순수 함수라 과거 조건 벡터만 저장해두면 백테스트와 그리드서치가 그대로 된다.

## 포인트 추가

`www/index.html`의 `POINTS` 배열에 추가한다.

```js
{id:'...', name:'○○항', admin:'○○', sea:'E',
 lat:37.0575, lon:129.4272,
 terrain:['breakwater','rock','sand'],   // sand rock mixed breakwater reef weed estuary
 reef:1,      // 인공어초 유무
 light:1,     // 상야등 유무 — 야행성 어종 야간 조도 팩터에 반영
 range:.25}   // 평균 조차 m (조석 캐시 없을 때 근사용)
```

`terrain` 태깅은 간조 시각에 촬영된 위성사진을 보고 판단하는 게 가장 정확하다.
수중여와 모래-암반 경계가 그대로 드러난다.

## 주의

구명조끼 착용은 갯바위·방파제에서 법적 의무다. 금어기, 금지체장, 출입통제구역은
매년 바뀌므로 출조 전 별도로 확인해야 한다. 이 앱은 그 정보를 제공하지 않는다.
